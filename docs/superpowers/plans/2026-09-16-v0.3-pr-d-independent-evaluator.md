# Idea Vending Machine v0.3 PR D — Independent Evaluator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a provider-neutral independent evaluator and deterministic decision engine that converts trusted PR C candidates plus Evidence Graph artifacts into auditable `GO`, `MODIFY`, `HOLD`, or `KILL` results without allowing probabilistic model output to own official decisions.

**Architecture:** Add four isolated modules: raw-idea baseline contract, evaluator contract, provider-neutral evaluator boundary, and deterministic decision engine. Probabilistic critique remains untrusted; all IDs, evidence references, confidence, selected concept, official verdict, and state updates remain deterministic and fail closed.

**Tech Stack:** Python 3.11 stdlib, existing `src/idea_vending` contracts, `unittest`, GitHub Actions Production Gate.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-pr-d-independent-evaluator-design.md`

## Global Constraints

- Preserve existing v0.1/v0.2/PR A/PR B/PR C behavior.
- No live LLM/search provider, database, auth, billing, SaaS layer, or final Executive UX in PR D.
- Official dimension statuses are exactly `strong`, `mixed`, `weak`, `unknown`.
- Official decisions remain exactly `GO`, `MODIFY`, `HOLD`, `KILL`.
- Provider output may not set official decision, confidence, selected concept ID, trusted IDs, Agent MD levels, or Evidence Graph confidence tiers.
- Missing evidence alone may cause `HOLD`, never `KILL`.
- `GO` keeps the original idea. `MODIFY` selects one trusted evolved candidate.
- `GO`/`MODIFY` with low confidence is prohibited.
- Multiple qualifying evolved candidates without strict dominance must produce `HOLD`.
- Human approval remains separate and is never set by PR D.
- Every task follows RED → GREEN → full Production Gate evidence.

### Task 5: GO / MODIFY / HOLD / KILL Decision Engine

**Files:**
- Modify: `src/idea_vending/decision_engine.py`
- Modify: `tests/test_decision_engine.py`

**Interfaces:**
- Produces: `decide_evolution(...) -> dict[str, Any]`, `apply_decision_to_state(state, decision_result, candidates) -> dict[str, Any]`.

- [ ] **Step 1: Write failing verdict tests**

Required cases:
- eligible baseline + no materially better candidate → `GO`, selected ID null;
- one eligible candidate with material Evolution Delta → `MODIFY` and trusted candidate ID;
- two qualifying candidates with no strict dominance → `HOLD` and comparison-validation action;
- one candidate strictly dominates every other qualifying candidate → `MODIFY`;
- unresolved material evidence/collision → `HOLD`, never `KILL`;
- baseline and every candidate evidence-backed eliminated → `KILL`;
- missing evidence alone → `HOLD`;
- `MODIFY` writes `selected_concept_id` and candidate `one_sentence_concept` to string-valued `evolved_idea`;
- `GO` keeps original handoff semantics;
- PR D never sets `human_decision`.

- [ ] **Step 2: Run Production Gate and verify RED**

- [ ] **Step 3: Implement verdict derivation**

Comparison order for evidence-backed statuses is `weak < mixed < strong`; `unknown` causes HOLD when decision-critical. `MODIFY` requires improvement in at least two dimensions including at least one anchor dimension, no worsening that creates a hard blocker, and strict dominance for multi-finalist selection.
