# Idea Vending Machine v0.3 PR A — Executive Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the deterministic v0.3 Evolution State, executive-summary-first report contract, human decision state, and guarded handoff into the existing v0.2 development-package generator.

**Architecture:** Add a pure Python domain module that owns v0.3 state and report validation, plus a separate handoff module that is the only v0.3 path into `generate_development_package()`. PR A deliberately does not perform web research, candidate generation, model calls, persistence, or UI work; later PRs populate the schema defined here.

**Tech Stack:** Python 3.11 standard library, `unittest`, existing `scripts/verify.py`, existing GitHub Actions Production Gate.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-executive-innovation-report-design.md`

## Global Constraints

- Preserve the user's original idea verbatim in v0.3 state.
- Decisions are exactly `GO`, `MODIFY`, `HOLD`, or `KILL`.
- Confidence is exactly `high`, `medium`, or `low`.
- The executive brief is summary-first and must expose uncertainty rather than bury it.
- A complete report must contain both executive and detailed-analysis layers.
- Evidence references are claim IDs only in PR A; evidence-record storage is PR B.
- `HOLD` and `KILL` must never hand off to v0.2 package generation.
- `GO` and `MODIFY` require explicit human `proceed` approval before handoff.
- Existing `/api/analyze` and `/api/package` behavior must remain backward compatible in PR A.
- No third-party dependency is added.
- `scripts/verify.py` remains the single Production Gate entry point.
- `NO GREEN WITHOUT EVIDENCE` remains mandatory.

The executive brief must contain these exact top-level keys:

```python
{
    "thesis",
    "why_now",
    "evolution_delta",
    "market_snapshot",
    "best_customer",
    "business_value",
    "reasons_for",
    "reasons_against",
    "critical_unknowns",
    "cheapest_next_validation",
    "evidence_refs",
}
```

`reasons_for` and `reasons_against` must each contain exactly three non-empty strings. `critical_unknowns` must contain at least one non-empty string. `cheapest_next_validation` must contain non-empty `action`, `pass_condition`, and `fail_condition` strings.

`market_snapshot` must contain:

```python
{
    "stage": str,
    "current_market": list,
    "forecast_market": list,
    "growth": list,
    "buyer": str,
}
```

Each market/growth entry is a PR-A placeholder structure for future evidence-population, but if present it must include `label` and `evidence_refs` fields. PR A does not manufacture market numbers.

### Task 3: Human Decision and Guarded v0.2 Handoff

**Files:**
- Create: `src/idea_vending/evolution_handoff.py`
- Create: `tests/test_evolution_handoff.py`
- Do not change: public behavior of `app.py`

**Interfaces:**
- Consumes: a complete validated v0.3 evolution state.
- Produces: `can_handoff_to_development(state: dict[str, Any]) -> bool`
- Produces: `generate_approved_development_package(state: dict[str, Any]) -> dict[str, str]`

Handoff rules:

```text
GO + human_decision=proceed + complete report => allowed
MODIFY + human_decision=proceed + evolved_idea present + complete report => allowed
HOLD => blocked
KILL => blocked
missing human decision => blocked
report_status != complete => blocked
MODIFY without evolved_idea => blocked
```

When allowed, the handoff idea is:
- `GO`: `evolved_idea` if non-empty, otherwise `raw_idea`.
- `MODIFY`: mandatory `evolved_idea`.

Before calling v0.2, run `analyze_idea(handoff_idea)` and then `generate_development_package(handoff_idea, analysis)`.

- [ ] **Step 3: Implement the smallest handoff module** with no HTTP/UI changes.
- [ ] **Step 4: Re-run** handoff tests and existing v0.2 package-generator tests.
