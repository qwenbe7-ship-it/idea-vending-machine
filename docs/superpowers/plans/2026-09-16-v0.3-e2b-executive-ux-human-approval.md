# v0.3 E2B Executive UX + Human Approval + Browser E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/api/evolve` the primary browser flow, persist completed trusted assessments in a bounded in-memory store, require server-side human approval before development-package generation, render the full executive/reality-evaluation experience safely, and prove the flow in real Chromium without paid provider calls.

**Architecture:** Add one focused in-memory `AssessmentStore` that stores validated completed evolution results keyed by trusted `runtime_id`. Extend `app.py` with persistence on completed `/api/evolve` responses and a new `POST /api/evolve/approve` endpoint that accepts only `runtime_id`, reloads server-owned state, sets `human_decision="proceed"`, and delegates to the existing `generate_approved_development_package()`. Replace the legacy document-first browser flow with safe DOM rendering of runtime events, Executive Decision, ten Reality Cards, detailed/evidence sections, and guarded approval. Browser E2E runs in a separate deterministic CI job with Python Playwright + Chromium and injected fake providers; live provider smoke remains separate.

**Tech Stack:** Python 3.11 stdlib production runtime, HTML/CSS/vanilla JS, `unittest`, Python Playwright `1.63.0` test-only dependency, Chromium, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-e2-ten-candidate-executive-ux-design.md`

## Global Constraints

- `/api/evolve` accepts only `{"idea":"..."}`; browser/provider/model/decision/confidence/selected-concept/human-decision overrides remain forbidden.
- `POST /api/evolve/approve` accepts only `{"runtime_id":"..."}`.
- Only validated completed assessments may be stored or approved.
- Only official `GO` or `MODIFY` may produce a development package.
- Server, never browser, sets `human_decision = "proceed"`.
- Existing `generate_approved_development_package()` remains the handoff authority.
- `HOLD`, `KILL`, `incomplete`, and `failed` must never create a development package.
- Store is memory-only, bounded, expiring, and returns defensive copies.
- Existing `/api/analyze` and `/api/package` semantics remain unchanged.
- Frontend uses safe DOM APIs only; no `innerHTML`, `outerHTML`, or `document.write`.
- Evidence links may only be rendered from server-validated HTTP(S) evidence URLs and use `rel="noopener noreferrer"` when opened externally.
- Normal CI must not call a paid/live provider.
- Browser GREEN is distinct from LIVE PROVIDER GREEN.
- Browser dependency is test-only: `playwright==1.63.0`; install only Chromium in CI.
- No SaaS accounts, database, billing, arbitrary code execution, or client-selected winner override.

- [ ] **Step 3: Implement the minimal store**

Use `OrderedDict` and defensive `deepcopy`:

```python
class AssessmentStore:
    def save_completed(self, result):
        runtime = result.get("runtime")
        state = result.get("state")
        graph = result.get("evidence_graph")
        validate_runtime_record(runtime)
        if runtime["status"] != "completed":
            raise ValueError("only completed assessments can be stored")
        validate_complete_report(state)
        validate_state_evidence_against_graph(state, graph)
        if runtime["evolution_id"] != state["evolution_id"]:
            raise ValueError("runtime and state evolution_id must match")
        runtime_id = runtime["runtime_id"]
        self._records[runtime_id] = {
            "runtime_id": runtime_id,
            "evolution_id": runtime["evolution_id"],
            "result": deepcopy(result),
            "created_at": self._clock(),
            "approved": False,
            "documents": None,
        }
        self._evict_expired_and_over_capacity()
        return runtime_id
```

`mark_approved()` must deep-copy and store the approved trusted state + documents, and replay the same stored documents rather than regenerate them.

### Type consistency

`AssessmentStore.save_completed()` stores the full trusted result; `get()` and `mark_approved()` return defensive record copies. The approval endpoint uses only the stored `result["state"]`, sets human approval server-side, calls `generate_approved_development_package()`, and writes the deterministic package back through `mark_approved()`. Frontend approval consumes only `runtime_id` and receives exactly the document dictionary produced by that endpoint.
