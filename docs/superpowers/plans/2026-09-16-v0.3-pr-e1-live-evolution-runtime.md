# Idea Vending Machine v0.3 PR E1 — Live Evolution Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the merged v0.3 A–D contracts into one provider-backed evolution runtime with truthful runtime state, a mandatory `/api/evolve` endpoint, and an opt-in live-provider smoke check without making paid external APIs part of CI.

**Architecture:** Keep the Evolution Core provider-neutral. Add a runtime state contract, a stdlib HTTPS transport, an OpenAI Responses adapter, and one orchestration entry point that injects research/ideation/evaluation providers. All external outputs remain untrusted until existing deterministic validators admit them. Technical/provider failures produce `incomplete` with no official decision; business HOLD/KILL remain outputs only of a completed assessment.

**Tech Stack:** Python 3.11 stdlib, `urllib.request`, existing unittest-based Production Gate, OpenAI Responses API for optional live operation.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-pr-e1-live-evolution-runtime-design.md`

## Global Constraints

- Preserve `/api/analyze` and `/api/package` semantics.
- Add mandatory `POST /api/evolve`; client controls only `idea`.
- No API key/model/system prompt/provider URL/tool definition accepted from the browser.
- No new required runtime dependency; production transport remains Python stdlib.
- CI must not require a paid/live provider credential.
- Provider output never owns trusted IDs, official verdict, confidence, selected concept, or human approval.
- Technical/config/provider failures leave `Evolution State.decision` unset.
- Do not invent publication dates, geography, market definitions, or unsupported source metadata.
- `retrieved_at` may be runtime-generated; `publication_date` must be source-backed.
- No hidden chain-of-thought or authorization secret is logged/persisted.
- Live model IDs are configuration, not business logic.
