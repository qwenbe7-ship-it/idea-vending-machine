# Idea Vending Machine v0.3 — PR C Reframing + Candidate Forge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the v0.3 creative-intelligence layer that converts evidence-grounded raw ideas into structurally different, evidence-traceable candidate concepts without allowing model output to select a winner or bypass deterministic validation.

**Architecture:** PR C uses a Hybrid Expert Forge. Provider-facing ideation is probabilistic and injected behind a provider-neutral contract; all assumption, transformation, mechanism, candidate, diversity, causal-chain, evidence, and research-request admission rules are deterministic Python. Provider output is untrusted until validated and IDs are assigned by deterministic code.

**Tech Stack:** Python 3.11+ standard library, `unittest`, existing `Evidence Graph`, existing `Research Engine`, GitHub Actions Production Gate.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-pr-c-reframing-candidate-forge-design.md`

## Global Constraints

- No external runtime dependencies.
- No live LLM/search vendor adapter in this PR; providers are injected behind a protocol and tests use fakes.
- Provider output is untrusted structured data until deterministic validation passes.
- PR C must never set `GO`, `MODIFY`, `HOLD`, `KILL`, a winner, a score, or an approval field.
- Material factual references must resolve to existing `Evidence Graph` claim IDs.
- Unknown or unsupported factual questions become explicit Collision Research requests.
- IDs for assumptions, transfers, candidates, and research requests are deterministic and generated by trusted code.
- Four candidate families are canonical: `adjacent_innovation`, `category_shift`, `zero_based_reinvention`, `axion_candidate`.
- Preserve v0.2 and PR A/PR B behavior and tests.
- Release rule remains `NO GREEN WITHOUT EVIDENCE`.

- [ ] **Step 1: Write RED tests for exact assumption vocabulary and evidence references.**

Tests must assert:
- assumption type is exactly one of `workflow`, `customer_behavior`, `business_model`, `technology`, `regulation`, `distribution`, `data`, `economics`;
- status is exactly one of `supported`, `weak`, `contested`, `unsupported`, `unknown`;
- assumption IDs begin `assumption_` and are byte-stable for identical normalized inputs;
- supporting/contradicting claim IDs must exist in the supplied Evidence Graph;
- provider-supplied IDs are not accepted by constructors;
- challenge records require non-empty `challenge_question`, `remove_or_invert_test`, `expected_effect_if_false`, `new_opportunity_if_false`, `new_risk_if_false`.

- [ ] **Step 2: Run `python -m unittest tests.test_reframing -v` and verify RED because `reframing` does not exist.**

- [ ] **Step 3: Implement minimal deterministic constructors and validators.**

Use `hashlib.sha256` over a canonical JSON serialization (`sort_keys=True`, compact separators) to derive 12-hex suffix IDs. Transformation vocabulary is exactly:

```python
TRANSFORMATIONS = {
    "AFTER_TO_BEFORE", "REPAIR_TO_PREVENT", "SEARCH_TO_PREDICT",
    "ADVISE_TO_EXECUTE", "INPUT_TO_OBSERVE", "TOOL_TO_WORKFLOW",
    "WORKFLOW_TO_INFRASTRUCTURE", "DOCUMENT_TO_DATA", "DATA_TO_DECISION",
    "DECISION_TO_ACTION", "SERVICE_TO_ASSET", "ONE_TIME_TO_COMPOUNDING",
}
```

Each transformation record has exactly `transformation`, `applicable`, `reason`, `resulting_reframe`, `materiality`; materiality is `none`, `minor`, or `material`.

`audit_reframing_readiness()` returns:

```python
{
    "generation_ready": bool,
    "material_transformations": list[str],
    "tested_count": int,
    "original_remains_strong": bool,
}
```

It is ready only with at least two distinct `material` transformations, unless `original_remains_strong=True` is explicitly supplied.
