# v0.3 E2A Ten-Candidate Reality Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand Candidate Forge from four to exactly ten mandatory business candidate families and produce an evidence-aware deterministic Reality Verdict for every candidate before the project-level decision engine runs.

**Architecture:** Keep provider creativity untrusted and reuse the existing PR C/PR D deterministic contracts. The provider must emit one draft for each canonical family, deterministic code creates trusted candidate IDs, admission verifies exact family coverage/diversity/causal integrity, the independent evaluator critiques baseline plus all ten candidates, and a new Reality Verdict layer derives ADVANCE/REVISE/HOLD/REJECT without replacing GO/MODIFY/HOLD/KILL.

**Tech Stack:** Python 3.11 stdlib, unittest, existing Evidence Graph / Candidate Forge / Independent Evaluator / Decision Engine, GitHub Actions Production Gate.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-e2-ten-candidate-executive-ux-design.md`

## Global Constraints

- Successful E2A runs create exactly ten candidates and exactly ten unique canonical families.
- No `non_applicable_families` escape hatch remains in the E2A admission path.
- Provider output cannot set candidate IDs, Reality Verdicts, confidence, selected concept, official decision, or human approval.
- Every candidate must keep explicit unknowns or validation questions and a complete causal value chain.
- Every candidate receives all ten existing evaluation dimensions.
- Reality Verdict vocabulary is exactly `ADVANCE`, `REVISE`, `HOLD`, `REJECT`.
- Missing or contradictory decision-critical evidence is `HOLD`, not `REJECT`.
- Project-level `GO / MODIFY / HOLD / KILL` semantics remain authoritative and separate.
- Existing `/api/analyze`, `/api/package`, and E1 runtime failure semantics must not regress.
- No SaaS account system, database, billing, or client-controlled provider configuration.

- [ ] **Step 3: Implement minimal deterministic derivation**
