# v0.3 Production Pilot Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Idea Vending Machine safely deployable on Render with observable liveness/readiness and a sanitized public deployment smoke check.

**Architecture:** Keep the current Python stdlib HTTP server and provider boundary. Add passive liveness/readiness endpoints, environment-driven server binding, and a stdlib-only deployment checker. Render remains a thin deployment layer; provider credentials stay server-owned and are never required by deterministic CI.

**Tech Stack:** Python 3.11 stdlib, unittest, GitHub Actions, Render Python web service.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.3-production-pilot-readiness-design.md`

## Global Constraints

- Preserve all existing `/api/analyze`, `/api/package`, `/api/evolve`, `/api/evolve/approve` semantics.
- `/healthz` never contacts an external provider.
- `/readyz` checks provider configuration only and never performs a paid request.
- No secret, provider body, or exception text may appear in readiness responses.
- Production runtime must not depend on Playwright.
- Missing provider configuration must remain a truthful 503 state, never a business HOLD/KILL.
- No database, SaaS account system, or billing layer.
