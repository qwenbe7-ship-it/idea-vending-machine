## 1. Executive Summary

PR E1 connects the already-merged v0.3 A–D contracts into one executable, provider-backed evolution runtime without yet building the final Executive UX.

The runtime must be able to take one raw idea through:

```text
RAW IDEA
  ↓
LANDSCAPE RESEARCH
  ↓
EVIDENCE GRAPH
  ↓
ASSUMPTION MAP / REFRAMING
  ↓
MECHANISM TRANSFER / CANDIDATE FORGE
  ↓
COLLISION RESEARCH
  ↓
INDEPENDENT EVALUATION
  ↓
DETERMINISTIC DECISION ENGINE
  ↓
GO / MODIFY / HOLD / KILL
  ↓
EXECUTIVE REPORT DATA
```

PR E1 is deliberately not a UI PR. Its job is to prove that the complete v0.3 reasoning pipeline can execute through explicit provider interfaces while preserving every trust boundary established by PR A–D.

**Core rule:** external provider output never owns trusted IDs, evidence facts, official verdicts, confidence, selected concept, or human approval.

---

## 2. Why PR E1 Exists Separately from PR E2

A single large PR containing live providers, orchestration, HTTP streaming, UI, and browser E2E would make failures difficult to localize.

The approved decomposition is:

- **PR E1:** live provider adapter + runtime orchestration + execution-state contract + `/api/evolve` machine API + deterministic integration tests.
- **PR E2:** summary-first Executive UX + real progress rendering + evidence drill-down + human approval UX + browser E2E + final v0.3 release gate.

This means PR E1 must be independently testable without a browser and without requiring a live API key in CI.

## 4. Provider Architecture

### 4.1 Provider roles

PR E1 introduces three logical provider roles:

```text
ResearchProvider
IdeationProvider
EvaluationProvider
```

They are separate logical contexts even when they use the same vendor.

The evaluator must not receive the generator's hidden reasoning, prompt transcript, preferred candidate, or generator score.

### 4.2 Initial OpenAI adapter

The first live adapter targets the OpenAI Responses API through a small transport boundary.

Current official API documentation supports:

- Responses API model calls
- built-in `web_search`
- inline URL citations
- complete consulted URL lists through `web_search_call.action.sources`
- Structured Outputs with strict JSON Schema

Reference documentation:

- https://developers.openai.com/api/docs/guides/tools-web-search
- https://developers.openai.com/api/docs/guides/structured-outputs
- https://platform.openai.com/docs/models

The current model catalog identifies configurable GPT-5.6 family model IDs, including `gpt-5.6-sol`, `gpt-5.6-terra`, and `gpt-5.6-luna`.

Initial defaults:

```text
IVM_RESEARCH_MODEL=gpt-5.6-terra
IVM_REASONING_MODEL=gpt-5.6-sol
IVM_JUDGE_MODEL=gpt-5.6-sol
```

These are deployment defaults, not business-logic constants. All remain overridable through server-side configuration.

### 4.3 No new runtime dependency requirement

To preserve the project's stdlib runtime posture, the initial implementation should use a narrow HTTP transport built on Python stdlib (`urllib.request` or equivalent), rather than requiring the OpenAI Python SDK.

The provider-specific request/response mapping stays behind the adapter. Replacing the transport or adding another vendor later must not alter the Evolution Core contracts.

### 4.4 Configuration

Expected environment configuration:

```text
OPENAI_API_KEY
IVM_RESEARCH_MODEL
IVM_REASONING_MODEL
IVM_JUDGE_MODEL
IVM_PROVIDER_TIMEOUT_SECONDS
```

Secrets must never be returned through API responses, stored in Evolution State, written into evidence metadata, or logged.

Missing credentials are a runtime configuration failure and must not create any official business verdict.

## 5. New Components

Recommended implementation boundaries:

```text
src/idea_vending/
  provider_transport.py
  openai_provider.py
  evolution_runtime.py
  runtime_schema.py
```

### `provider_transport.py`

Owns only:

- HTTPS POST to provider endpoint
- authorization header injection
- JSON encode/decode
- timeout handling
- bounded response size
- provider HTTP/error normalization

It must not understand business decisions or mutate project state.

### `openai_provider.py`

Owns provider-specific conversion for:

- research requests → Responses API web-search request
- source/citation extraction
- ideation requests → strict structured output
- evaluator requests → strict structured output
- provider metadata extraction (response ID, model, usage when available)

It does not create official verdicts or trusted domain IDs.

### `runtime_schema.py`

Defines a stable execution record separate from `Evolution State`.

Minimum fields:

```text
runtime_id
evolution_id
status
current_stage
stage_events
provider_runs
failure
started_at
completed_at
```

Statuses:

```text
pending
running
completed
incomplete
failed
```

Stages:

```text
capture
landscape_research
assumption_analysis
reframing
mechanism_transfer
candidate_forge
collision_research
independent_evaluation
decision
report_assembly
```

The runtime record is operational evidence; it is not the Executive Report.

### `evolution_runtime.py`

The single orchestration entry point.

Suggested public function:

```python
run_evolution(
    idea,
    *,
    research_provider,
    ideation_provider,
    evaluation_provider,
    now_provider,
    event_sink=None,
) -> dict
```

Dependencies are injected so tests can run deterministically with fake providers.

## 6. Runtime State Machine

```text
PENDING
  ↓
CAPTURE
  ↓
LANDSCAPE_RESEARCH
  ├─ provider/config/transport failure → INCOMPLETE, NO OFFICIAL VERDICT
  ├─ completed research exposes material unknown → continue toward HOLD
  └─ evidence-ready
        ↓
ASSUMPTION_ANALYSIS
  ↓
REFRAMING
  ↓
MECHANISM_TRANSFER
  ↓
CANDIDATE_FORGE
  ├─ admission blocked by unresolved material question → HOLD-capable path
  ├─ provider/runtime failure → INCOMPLETE, NO OFFICIAL VERDICT
  └─ forge-ready
        ↓
COLLISION_RESEARCH
  ├─ completed research leaves material collision unresolved → HOLD-capable path
  ├─ provider/runtime failure → INCOMPLETE, NO OFFICIAL VERDICT
  └─ sufficient collision evidence
        ↓
INDEPENDENT_EVALUATION
  ├─ evaluator unavailable/malformed → INCOMPLETE, NO OFFICIAL VERDICT
  └─ validated critiques
        ↓
DETERMINISTIC_DECISION
        ↓
REPORT_ASSEMBLY
        ↓
COMPLETED
```

**Important distinction:**

- `failed` = an internal trusted-state invariant failed; no safe product result exists and no business verdict is emitted.
- `incomplete` = a technical/config/provider failure prevented a valid assessment from completing; `Evolution State.decision` remains unset.
- `completed` = the assessment contract completed and may validly end in GO, MODIFY, HOLD, or KILL.

A valid **HOLD** is a business conclusion based on completed assessment artifacts showing unresolved material uncertainty. It is not a substitute for technical failure.

Therefore:

```text
provider timeout ≠ HOLD
provider timeout ≠ KILL
provider timeout ≠ GO
```

A KILL can be a successful runtime completion. A provider timeout cannot.

## 7. Research Provider Contract

### 7.1 Web-search request

The OpenAI research adapter uses the Responses API `web_search` tool.

The adapter should request complete consulted sources where supported:

```text
include: ["web_search_call.action.sources"]
```

Inline citations and source URL metadata are treated as provider evidence inputs, not trusted facts.

### 7.2 Evidence normalization

A provider result may enter `Research Engine` only after it is converted into existing Evidence Records.

The adapter must never invent required evidence fields to satisfy validation.

Examples:

- unknown publication date → record is quarantined/rejected, not assigned today's date
- unknown geography → record cannot masquerade as a global claim
- absent market definition → market-size evidence cannot be admitted
- unsupported number → remains provider text/hypothesis, not a market-size fact

`retrieved_at` may use the runtime date because it describes our retrieval event. `publication_date` describes the source and must be source-backed.

### 7.3 Source coverage

Landscape research must preserve the existing requirement for explicit counter-evidence.

Collision research must preserve required coverage for:

- `prior_art`
- `competitors`
- `failure_or_blockers`

If the provider call itself succeeds but admissible research reveals that a material question is unresolved, that uncertainty may feed a legitimate HOLD path.

If the provider fails technically before the required research can be performed, the runtime is incomplete and no official verdict is emitted.

## 8. Ideation Provider Contract

The live ideation adapter implements the already-existing `IdeationProvider.generate(request)` boundary.

Each PR C operation is executed as a separate structured request:

- `extract_assumptions`
- `challenge_assumptions`
- `propose_reframes`
- `discover_mechanisms`
- `forge_candidates`

The OpenAI adapter should use strict Structured Outputs for the provider-facing shape where feasible.

Even valid JSON remains untrusted until existing deterministic constructors/validators:

- create trusted IDs
- validate Evidence Graph claim references
- validate transformations
- validate causal mechanism chain
- validate candidate family
- validate causal value chain
- run diversity/family/admission gates

The model cannot submit trusted `assumption_id`, `transfer_id`, `candidate_id`, scores, rankings, or final decisions.

---

## 9. Independent Evaluation Provider Contract

The evaluator call must use a fresh, isolated provider request built only from the existing `build_evaluation_request()` output.

Forbidden evaluator inputs:

- generator hidden reasoning
- generator ranking
- selected winner
- official decision
- official confidence

The evaluator returns only the existing critique schema.

Its recommendation is advisory. `decision_engine.py` remains the sole owner of official `GO / MODIFY / HOLD / KILL` derivation.

The provider must not set `human_decision` under any condition.

## 10. Execution Events

PR E1 emits truthful stage events so PR E2 can render real progress rather than simulated progress.

Event shape:

```text
runtime_id
evolution_id
sequence
stage
status
message_code
occurred_at
```

Allowed event statuses:

```text
started
completed
blocked
failed
```

Messages are stable codes, not arbitrary provider prose.

Examples:

```text
landscape_research_started
landscape_research_completed
candidate_forge_blocked
collision_research_completed
independent_evaluation_failed
decision_completed
```

The event sink is optional in core tests and will be consumed by PR E2 for real browser progress.

## 11. Public API Boundary

PR E1 **must add** a synchronous machine-facing endpoint:

```text
POST /api/evolve
```

Request:

```json
{
  "idea": "..."
}
```

Success response returns machine-facing runtime/result data, not final polished Executive UX.

The endpoint accepts only the idea as client-controlled evolution input. It must not accept model names, API keys, system prompts, arbitrary provider URLs, tool definitions, or trusted decision fields from the browser.

Provider configuration is server-side only.

Backward compatibility:

```text
POST /api/analyze   unchanged
POST /api/package   unchanged
```

PR E2 may add a streaming endpoint or a streaming wrapper around the same runtime event sink. PR E1 must not fake progress with timers.

## 12. Failure Taxonomy

Canonical runtime failure codes are closed-vocabulary.

Minimum categories:

```text
provider_not_configured
provider_auth_failed
provider_rate_limited
provider_timeout
provider_http_error
provider_invalid_json
provider_schema_mismatch
research_insufficient
research_source_metadata_insufficient
candidate_admission_blocked
collision_research_incomplete
evaluator_unavailable
internal_contract_violation
```

Mapping rules:

- API key missing → `provider_not_configured`, runtime incomplete, official decision unset
- 401/403 → `provider_auth_failed`, runtime incomplete, official decision unset
- 429 → `provider_rate_limited`, runtime incomplete, official decision unset
- timeout → `provider_timeout`, runtime incomplete, official decision unset
- malformed structured output → schema mismatch, runtime incomplete, official decision unset
- Evidence Record cannot be normalized → quarantine + continue if safe; if the research operation still completes but a material evidence question remains unresolved, the later Decision Engine may produce HOLD
- material evidence unresolved after completed research → HOLD is allowed
- all options evidence-backed eliminated → KILL may be produced by Decision Engine
- internal trusted-state invariant failure → runtime failed; do not manufacture HOLD/KILL

No technical/provider failure may be transformed into GO, MODIFY, HOLD, or KILL.

## 13. Auditability and Provider Run Metadata

Every live provider call must retain non-secret audit metadata where available:

```text
provider
provider_response_id
role
model
operation/pass
started_at
completed_at
status
usage metadata
source count (research only)
```

Do not persist:

- API keys
- authorization headers
- hidden chain-of-thought
- raw internal reasoning traces

The product may retain user-visible structured outputs and source metadata, but not hidden model reasoning.

## 14. Determinism Boundary

Live provider generation itself is not deterministic.

The runtime must therefore distinguish:

### Non-deterministic assets

- retrieved research text
- model-produced assumptions/reframes/mechanisms/candidate drafts
- evaluator critiques

### Deterministic trusted processing

- schema validation
- source/evidence admission
- trusted ID creation
- Evidence Graph mutation
- market-integrity checks
- candidate admission
- hard gates
- confidence computation
- official decision
- handoff eligibility

A successful provider response is not equivalent to successful evolution.

## 15. Testing Strategy

### 15.1 CI must not depend on a paid external API

All normal Production Gate tests use deterministic fake transports/providers.

Tests must cover:

- exact provider request shape
- Authorization secret never returned/logged
- timeout/error normalization
- source extraction
- missing source metadata quarantine
- malformed JSON rejection
- strict ideation schema ingestion
- evaluator isolation
- provider attempts to set official fields
- stage event ordering
- complete GO path
- complete MODIFY path
- completed research with material unknown → HOLD
- evidence-backed total elimination → KILL
- provider timeout → incomplete with decision unset
- missing API key → incomplete with decision unset
- `/api/evolve` request/response and server-side configuration boundary
- `/api/analyze` regression
- `/api/package` regression

### 15.2 Optional live smoke verification

Add an explicit opt-in command:

```text
python scripts/verify_live_provider.py
```

It runs only when valid provider credentials are supplied.

It must verify at minimum:

- Responses API connectivity
- configured model access
- web search tool response
- source/citation extraction
- strict structured output parse

This smoke check is separate from deterministic CI so CI remains reliable.

**Release truthfulness rule:** until a live smoke run has succeeded in the intended deployment environment, documentation must say the adapter is contract-tested but not live-verified there.

## 16. Security Requirements

- provider endpoint is hard-coded/allowlisted; browser cannot supply arbitrary URL
- API key read server-side from environment only
- no key in response bodies, logs, evidence, exceptions, or provider metadata
- request body remains bounded
- provider response body is size-bounded before parsing
- outbound timeout mandatory
- provider raw text is never interpreted as executable instructions
- source URLs are data only and never automatically fetched/executed by trusted code without a separate explicit adapter
- no shell execution
- no arbitrary filesystem writes
- no automatic code generation/execution from provider output

---

## 17. Cost and Latency Controls

PR E1 must expose deterministic limits in server configuration rather than letting providers loop freely.

Minimum controls:

```text
max research provider calls per pass
max ideation calls per evolution
max evaluator calls per evolution
provider timeout
max provider response bytes
max total runtime stage retries
```

Default retry policy should be conservative. Automatic retry is allowed only for transient technical failures and must never change a business verdict directly.

No unbounded agent loop is allowed.

---

## 18. Executive Report Assembly Boundary

PR E1 assembles the validated machine-facing report data required by PR A, but PR E2 owns presentation.

Report assembly must preserve:

- original idea verbatim
- evolved idea only for MODIFY
- decision and deterministic confidence
- evidence refs
- reasons for and against
- critical unknowns
- cheapest/next validation
- market-size definition metadata
- final decision basis

A report cannot be marked complete if its citations do not resolve to Evidence Graph claims.

## 20. Acceptance Criteria

PR E1 is ready for merge only when all of the following are demonstrated:

1. One injected-provider runtime function orchestrates A–D contracts without bypassing validators.
2. Research, ideation, and evaluator contexts are logically separated.
3. OpenAI Responses adapter supports current web-search source extraction and strict structured output mapping.
4. Required Evidence Record fields are never invented to make a provider response pass.
5. Technical/config/provider failure leaves official decision unset and cannot yield GO, MODIFY, HOLD, or KILL.
6. Completed assessment evidence containing unresolved material uncertainty can yield a legitimate HOLD.
7. Official verdict and confidence remain deterministic.
8. Provider cannot set trusted IDs, selected candidate, human approval, or official decision.
9. Runtime emits truthful ordered stage events.
10. `/api/analyze` and `/api/package` remain unchanged.
11. `/api/evolve` is implemented and accepts only the idea from the client as evolution input; provider configuration remains server-side.
12. Normal CI uses no live API credentials.
13. Optional live smoke verification exists and clearly distinguishes contract-tested from deployment-verified status.
14. Security tests prove secrets are not leaked.
15. Full Production Gate ends with `GREEN WITH EVIDENCE` before implementation PR merge.
