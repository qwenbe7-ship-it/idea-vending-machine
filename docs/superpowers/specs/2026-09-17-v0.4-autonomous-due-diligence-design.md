# v0.4 Autonomous Due Diligence Design

## Goal

Turn Idea Vending Machine from a ChatGPT copy/paste bridge into a one-input autonomous decision system. The normal product path is: idea input → server-owned research → candidate forge → adversarial/contradiction checks → independent judge → deterministic GO/MODIFY/HOLD/KILL → executive report → explicit human approval → spec/design/plan. ChatGPT Plus Bridge remains an advanced fallback only.

## Product rule

The user must not need to open ChatGPT, copy prompts, move JSON, understand Forge/Judge, or provide an API key in the browser. One primary action starts the full analysis. The server owns provider configuration and all trusted state.

## Architecture

Reuse the already-verified `run_evolution()` E2A runtime and OpenAI Responses API adapter rather than creating a parallel analysis engine. `run_evolution()` remains the source of truth for research, ten structurally distinct candidate families, collision/contradiction handling, independent evaluation, Reality Assessments, and deterministic decision logic.

The HTTP layer exposes `/api/evolve` as the autonomous product path. Provider configuration remains server-only. If the provider is not configured, `/api/evolve` fails closed with `provider_not_configured`; the UI explains that automatic analysis is not configured and reveals the ChatGPT Plus Bridge only under an explicit advanced fallback disclosure.

When provider configuration is valid, `/readyz.default_mode` becomes `autonomous_due_diligence`. Otherwise it remains `chatgpt_plus_bridge` so the service stays operational during setup. The readiness payload continues to expose both modes without secrets.

## Provider roles

Build separate role-aware provider instances for research, ideation, and judge, even though they share one server-owned API credential. This prevents mutable adapter metadata from one role being confused with another and keeps the judge invocation logically independent from Forge. Default models remain:

- research: `gpt-5.6-terra`
- ideation/reasoning: `gpt-5.6-sol`
- judge: `gpt-5.6-sol`

The OpenAI API documentation currently lists GPT-5.6 Sol and Terra as Responses API models and supports web search, so these existing defaults remain valid.

## Autonomous response evidence

Completed autonomous results receive a server-derived `automation_summary` that contains only facts derived from trusted runtime output:

- `mode`: `autonomous_due_diligence`
- `research_completed`: boolean
- `evidence_count`: integer
- `contradicting_evidence_count`: integer
- `candidate_count`: integer; completed run must be 10
- `independent_critique_count`: integer
- `decision`: GO/MODIFY/HOLD/KILL or null
- `runtime_id`: trusted runtime id or null

No model may set these fields. The server derives them after the deterministic runtime completes.

## UI

Default UI when API is configured:

1. Idea textarea.
2. One `자동 분석 시작` button.
3. While waiting, a visible workflow strip: `시장 조사 → 반증 탐색 → 10개 대안 → 독립 심사 → 최종 결정` with wording that these are server-run stages, not fake client-side completion.
4. On success, show an `AUTONOMOUS DUE DILIGENCE` evidence summary before the existing executive decision/report UI.
5. GO/MODIFY retains explicit human approval before spec/design/plan; HOLD/KILL remains blocked.

Default UI when API is not configured:

- Primary action remains visible but fails with a clear operator-configuration message rather than opening ChatGPT.
- A collapsed `고급 옵션 · ChatGPT Plus Bridge 사용` section exposes the existing bridge workflow as a fallback.
- Raw JSON and session details stay nested under Bridge advanced disclosure.

## Security and trust boundary

- Browser never submits provider model ids, API key, official decision, confidence, selected concept, or approval state.
- `/api/evolve` accepts exactly `{idea}`.
- Provider outputs remain untrusted and pass existing schema/evidence/deterministic gates.
- The judge cannot directly set GO/MODIFY/HOLD/KILL.
- Development handoff requires a server-stored completed assessment and explicit human approval.
- Existing CSP/XSS and request-size protections remain.

## Failure behavior

- Missing API configuration: 503 `provider_not_configured`; no fake result.
- Provider/runtime failure: fail closed; no official decision.
- Incomplete runtime: show incomplete/failed runtime state; no approval.
- Bridge remains a fallback but is not marketed as the primary product workflow.

## Acceptance criteria

1. With injected/fake autonomous runner, one browser click on `자동 분석 시작` calls `/api/evolve`, renders a completed executive result, ten candidates, evidence summary, and deterministic decision without showing Bridge copy/paste steps.
2. With provider configuration absent, readiness says Bridge is available and API is not configured; autonomous endpoint remains 503 and UI gives an operator-configuration message.
3. With provider configuration present, readiness default mode is `autonomous_due_diligence` and API mode is configured.
4. `automation_summary` is server-derived and cannot be supplied by the browser/provider.
5. GO/MODIFY approval behavior and HOLD/KILL blocking remain unchanged.
6. Existing Bridge tests continue to pass as fallback coverage.
7. Production Gate and real Chromium Gate are green before merge/deploy.
