# v0.3 Production Pilot Readiness Design

## Objective

Make the merged v0.3 application safely deployable as a public Python web service and make deployment readiness observable without exposing provider credentials or manufacturing business verdicts.

## Runtime contract

- `GET /healthz` is a process liveness probe. It returns HTTP 200 with `{"status":"ok"}` and does not contact external providers.
- `GET /readyz` is a configuration readiness probe. It validates server-owned OpenAI provider configuration only. It returns HTTP 200 with `{"status":"ready","provider":"configured"}` when provider configuration is syntactically valid, otherwise HTTP 503 with `{"status":"not_ready","reason":"provider_not_configured"}`.
- Neither endpoint returns API keys, model prompts, provider bodies, or exception text.
- Existing `/api/evolve` behavior remains fail-closed: missing provider configuration returns 503 and no business verdict.

## Server binding contract

- `main()` reads `HOST` and `PORT` from the server environment.
- Default host remains `127.0.0.1`; default port remains `8000` for local development.
- Deployment sets `HOST=0.0.0.0` and Render supplies `PORT`.
- Invalid ports fail startup rather than silently binding a different port.

## Deployment contract

- Render runtime: Python.
- Production build command performs a Python compilation check only; production has no browser-test dependency.
- Start command: `python app.py`.
- Region: Singapore.
- Initial plan: free for pilot validation.
- Auto-deploy is disabled during the first pilot so an unreviewed main push cannot silently change the pilot.
- Public deployment without `OPENAI_API_KEY` is allowed only as a liveness deployment; `/readyz` must remain 503 and live-pilot completion must not be claimed.

## Verification levels

1. `GREEN WITH EVIDENCE`: deterministic Python/unit/integration gate.
2. `BROWSER GREEN WITH EVIDENCE`: real Chromium E2E gate.
3. `DEPLOYMENT HEALTH GREEN`: public `/healthz` returns 200.
4. `LIVE PROVIDER GREEN WITH EVIDENCE`: opt-in `scripts/verify_live_provider.py` succeeds in an environment with the real provider credential.
5. `PRODUCTION PILOT GREEN`: deployed `/readyz` is 200 and one real idea completes the public `/api/evolve` flow without runtime failure, followed by human approval only for GO/MODIFY.

These labels are intentionally independent. Passing a lower level never implies a higher level.

## Public pilot smoke

Add a stdlib-only deployment verifier that accepts a base URL and checks `/healthz` and `/readyz`. It must sanitize failures and never print response bodies from provider-backed endpoints. A real idea pilot remains a deliberate opt-in step after provider readiness is GREEN.

## Security and operational boundaries

- Browser cannot supply `OPENAI_API_KEY`, model IDs, provider URL, official decision, confidence, selected candidate, or human approval.
- Health/readiness probes never call the paid provider.
- No database is added; the approved assessment store remains memory-only and expires on restart.
- No SaaS/account/billing architecture is added.
- No completion claim is allowed without fresh exact-head verification.
