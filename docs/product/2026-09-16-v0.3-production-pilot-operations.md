# v0.3 Production Pilot Operations

## Purpose

This runbook covers public deployment and production-pilot evidence for Idea Vending Machine v0.3 after the deterministic and real-Chromium gates are green.

The default production path is **ChatGPT Plus Bridge Mode**. OpenAI API mode remains optional and independent. Passing a lower evidence level never implies a higher one.

The rule for every stage is: **NO GREEN WITHOUT EVIDENCE**.

Do not set `PORT` manually. Render supplies `PORT`, and the application validates it before binding.

ChatGPT Plus Bridge Mode does **not** require a server-side OpenAI API key. The browser never receives provider credentials.

`OPENAI_API_KEY` is optional and enables the legacy/direct OpenAI API mode only. If API mode is intentionally enabled, the following optional server-only overrides also remain available:

```text
OPENAI_API_KEY
IVM_RESEARCH_MODEL
IVM_REASONING_MODEL
IVM_JUDGE_MODEL
IVM_PROVIDER_TIMEOUT_SECONDS
```

None of these values may be supplied by the browser or copied into a Bridge package.

## Health and readiness

`GET /healthz` is passive process liveness only. It never calls ChatGPT or an external provider.

Expected response:

```json
{"status":"ok"}
```

`GET /readyz` reports mode readiness. Bridge Mode is the default and remains ready without `OPENAI_API_KEY`.

Expected Bridge-first response when API mode is not configured:

```json
{
  "status": "ready",
  "default_mode": "chatgpt_plus_bridge",
  "modes": {
    "chatgpt_plus_bridge": "ready",
    "openai_api": "not_configured"
  }
}
```

If the optional API mode is configured, only the API-mode value changes:

```json
{
  "status": "ready",
  "default_mode": "chatgpt_plus_bridge",
  "modes": {
    "chatgpt_plus_bridge": "ready",
    "openai_api": "configured"
  }
}
```

A missing API key therefore does not make the Bridge deployment unready. It only means `/api/evolve` remains unavailable through the optional API path.

## Public deployment verifier

Run:

```bash
python scripts/verify_deployment.py https://<service-host>
```

The verifier checks exactly `/healthz` and `/readyz` with bounded network timeouts. It fails closed on legacy or unexpected readiness schemas and does not print provider-backed response bodies or credentials.

Bridge-ready without optional API mode:

```text
PASS: deployment health
PASS: ChatGPT Plus Bridge readiness
INFO: optional OpenAI API mode not configured
DEPLOYMENT BRIDGE READY WITH EVIDENCE
```

Bridge-ready with optional API mode:

```text
PASS: deployment health
PASS: ChatGPT Plus Bridge readiness
PASS: optional OpenAI API mode configured
DEPLOYMENT BRIDGE READY WITH EVIDENCE
```

## Bridge trust boundary

The public browser is an orchestration client, not a decision authority.

1. The server creates a Bridge session and the trusted Forge request package.
2. The owner runs that package in a fresh ChatGPT Plus conversation.
3. The returned Forge JSON is untrusted until the server validates its schema, evidence records, candidate family coverage, IDs, bounds, and state transition.
4. The server creates a trusted Judge package only after Forge validation succeeds.
5. The owner runs Judge in a **different fresh ChatGPT conversation** so generator preference is not carried into the independent evaluation.
6. The Judge result is also untrusted until the server validates it.
7. GO/MODIFY/HOLD/KILL is produced only by the deterministic server-side decision engine. ChatGPT output cannot directly set the official decision.
8. Development handoff remains blocked for HOLD/KILL. GO/MODIFY still requires explicit human approval before `spec.md`, `design.md`, and `plan.md` are produced.

Bridge packages and imports are bounded, versioned, stateful, replay-safe, and session-scoped. Do not bypass the server by treating copied ChatGPT JSON as an official result.

## Evidence labels

### 1. GREEN WITH EVIDENCE

`python scripts/verify.py` passed for the exact commit. This covers compilation, security contracts, unit tests, integration tests, HTTP behavior, runtime contracts, Bridge contracts, and optional provider-adapter contracts. It does not prove a real browser or a real ChatGPT Plus round trip.

### 2. BROWSER GREEN WITH EVIDENCE

The exact commit passed `python scripts/verify_browser.py` in real Chromium. The Bridge browser gate must prove all required scenarios, including Forge export/import, Judge export/import, GO approval, MODIFY approval, HOLD/KILL blocking, malformed import rejection, wrong-session rejection, replay behavior, XSS safety, and Bridge readiness without an API key.

The browser gate uses deterministic fixtures. It does not prove a real ChatGPT Plus response.

### 3. BRIDGE DEPLOYMENT READY WITH EVIDENCE

The deployed public service has the reviewed `main` commit, `/healthz` is valid, `/readyz` reports `chatgpt_plus_bridge` as the ready default mode, and the public root renders the Plus-first Bridge UX.

This proves deployment readiness, not a completed real AI round trip.

### 4. OPTIONAL API MODE GREEN WITH EVIDENCE

This label is separate from Bridge readiness. It applies only when API mode is intentionally configured and its live-provider smoke succeeds through the server-owned credential path.

Run only when API mode is part of the intended deployment:

```bash
python scripts/verify_live_provider.py
```

A successful API smoke does not substitute for the owner-operated Plus Bridge pilot.

### 5. PRODUCTION PILOT GREEN

This is the highest v0.3 pilot label. It requires all of the following evidence from the deployed public service:

1. The reviewed `main` SHA passed both deterministic and Chromium gates.
2. Render is serving that reviewed `main` revision.
3. `/healthz` is 200 with the expected liveness payload.
4. `/readyz` is 200 and reports `chatgpt_plus_bridge` as the ready default mode.
5. The public root visibly exposes the Plus-first Bridge flow.
6. One real business idea creates a Forge package on the public deployment.
7. A real owner-operated ChatGPT Plus conversation returns the Forge result and the deployed server accepts it.
8. A separate fresh ChatGPT Plus conversation returns the Judge result and the deployed server accepts it.
9. The server renders exactly ten admitted candidates/Reality Assessments and produces the official project decision only through the deterministic decision engine.
10. HOLD/KILL remains blocked. For GO/MODIFY, explicit owner approval succeeds and produces non-empty `spec.md`, `design.md`, and `plan.md`.

No deterministic fixture, API-mode smoke, local run, or single ChatGPT conversation may be described as `PRODUCTION PILOT GREEN`.

## Memory-only state limitation

The current `BridgeStore` and `AssessmentStore` are deliberately in-memory, bounded, and expiring. A process restart loses active Bridge sessions and stored assessments/approvals. This is acceptable for the first controlled pilot but means:

- no durable history across restarts;
- no cross-device recovery of an active session;
- no multi-instance shared state;
- Forge/Judge imports must finish before the Bridge session expires or the process restarts;
- GO/MODIFY approval must occur before the stored assessment expires or the process restarts.

This limitation must remain visible during the pilot. Do not imply database-backed persistence or SaaS account history.

```text

2. Open the implementation PR against main.
3. Confirm the PR merge-ref passes verify + browser-e2e.

5. Confirm the new main SHA passes verify + browser-e2e.
6. Trigger one reviewed deploy of the new main on the existing Render service.
7. Confirm the deployed revision matches the reviewed main revision.
8. Verify public /healthz and Bridge-first /readyz.
9. Verify the public root renders the Plus-first Bridge UX.
10. Enter one real business idea and export the public Forge package.
11. Run Forge in a fresh owner-operated ChatGPT Plus conversation and import the real JSON result.
12. Export Judge, run it in a different fresh ChatGPT Plus conversation, and import the real JSON result.
13. Verify the ten Reality Assessments and server-owned official decision.
14. For GO/MODIFY only, explicitly approve and verify non-empty spec.md, design.md, and plan.md.
15. Record the evidence and only then declare PRODUCTION PILOT GREEN.
```

The rule remains: **NO GREEN WITHOUT EVIDENCE**.
